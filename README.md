# 币安订单簿长跑记录器:可自证完整性的 L2 数据采集

7×24 小时采集币安现货 BTCUSDT、ETHUSDT 的增量深度推送,在本地重建订单簿,买卖前 10 档发生变化时记录一行,按小时落盘并压缩。设计目标是让数据**自证无漏**:任何断线、漏包或暂停都在文件中留下可检测的断点,而不会被静默拼接。用于为后续订单簿研究积累可公开的高频数据。

只使用币安公开行情接口,不需要 API key;仅依赖 Python 标准库与 `websockets`。

## 数据如何保证可信

| 机制 | 做法 |
|---|---|
| 更新编号首尾相接 | 每行带币安更新编号区间 `U, u`,要求本行 `U` = 上一行 `u` + 1;接不上即为断点,完整性报告统计断号次数 |
| 快照对齐 | 按币安规定的流程用 REST 快照与缓冲的增量事件对齐;快照早于缓冲区起点时重新获取,过旧视为断档 |
| 定时独立比对 | 每 10 分钟取一张 5000 档快照独立重建一本订单簿,在同一更新编号上与长跑订单簿逐档比对前 20 档;不一致时以快照替换。每次重新对齐后 60 秒先比对一次 |
| 实时自检 | 买一 ≥ 卖一(交叉),或价格超出快照覆盖范围时立即重新对齐,可疑行不写入 |
| 僵尸连接检测 | 整条连接 30 秒无消息、或单个品种 2 分钟无消息即判定失效并重连 |
| 事件留痕 | 重连、重新对齐、比对结果均带时间与原因写入 `logs/events.tsv` |
| 磁盘保护 | 磁盘剩余 < 10 GB 或本记录器数据 ≥ 5 GB 时暂停写盘(订单簿照常维护),暂停期在文件中表现为断点 |

`report` 命令从已落盘数据重算每天每品种一行的完整性报告:行数、首末时间、时段覆盖率、断号、同日超过 5 秒的时间缺口、交叉行数(应为 0)、重对齐次数、断线/僵尸次数、比对通过/不一致/跳过次数、数据体积。

## 测试

```bash
python3 -m unittest test_lob_daemon        # 27 项离线测试,不联网
```

测试以模拟交易所(FakeMarket)生成"标准答案"订单簿,逐项验证:有序事件重建与标准答案一致、首个事件须跨越快照编号、实时断档检测、零数量删档、行只在前 10 档变化时写出且编号连续、按小时切文件与压缩、丢包触发重新对齐并在文件中可见、快照失败退避且缓冲不溢出、比对器能发现并修复被篡改的订单簿、交叉盘与价格越界触发重新对齐、暂停留下可见断点、崩溃后文件尾修复、跨午夜断线不扭曲次日统计等。

记录器另有故障注入开关(环境变量 `LOB_TEST_DROP_AFTER`、`LOB_TEST_DISCONNECT_SEC`、`LOB_TEST_FREEZE_SEC`、`LOB_TEST_CORRUPT_AFTER`),可在真实连接上人为制造丢包、断线、冻结与订单簿篡改,检验对应的恢复路径。

## 运行

```bash
pip install websockets
python3 lob_daemon.py run        # 前台运行,Ctrl+C 停止
python3 lob_daemon.py status     # 实时健康状态
python3 lob_daemon.py report     # 完整性报告
```

macOS 下可用 `service.sh` 注册为 launchd 常驻服务(登录自启、崩溃 30 秒后拉起、运行期间阻止系统睡眠):

```bash
bash service.sh start | stop | restart | status | log | report
```

品种、档数、数据目录、阈值等可通过环境变量调整,见 `lob_daemon.py` 开头的配置段(如 `LOB_SYMBOLS`、`LOB_LEVELS`、`LOB_DATA_DIR`)。快照接口若所在网络无法直连,记录器读取系统代理设置访问;代理不可用期间状态显示"未对齐",不写入任何数据。

## 数据格式

```
data/BTCUSDT/2026-10-22/BTCUSDT_20261022_0100_p00.csv.xz
```

- 按交易所时间(UTC)每小时一个文件;写入中为 `.csv`,关闭后压缩为 `.csv.xz`。`p00`、`p01` 为同一小时内因重启产生的分段,按文件名排序即时间顺序。
- 前 10 档有任何变化记一行,每品种约每秒 8 行;两个品种合计约 30 MB/天。

| 列 | 含义 |
|---|---|
| `exch_ms` | 交易所事件时间(毫秒) |
| `local_ms` | 本机接收时间(毫秒) |
| `U`, `u` | 本行覆盖的更新编号区间 |
| `bid1_p`, `bid1_q` … `bid10_p`, `bid10_q` | 买一至买十的价格、数量 |
| `ask1_p`, `ask1_q` … `ask10_p`, `ask10_q` | 卖一至卖十的价格、数量 |

```python
import pandas as pd
df = pd.read_csv("sample/BTCUSDT_20261022_0100_p00.csv.xz")
```

`sample/` 中附两份样例:`BTCUSDT_20261022_0100_p00.csv.xz` 为长跑版的一个完整小时(29,806 行);`lob_demo_45s.csv` 为入门版 `lob_recorder.py` 录制的 45 秒前 5 档数据(格式不同,时间列为 `ts_ms`、编号列为 `lastUpdateId`)。

## 工程上踩过的坑

- **证书上下文须复用。** 为及时感知代理设置变化,每次 REST 请求重建 opener;但若同时每次新建 SSL 上下文,单次约 300 ms 且持有 GIL,会饿死 websocket 心跳线程,表现为 `keepalive ping timeout` 断线。现为代理每次现读、SSL 上下文全局复用。
- **launchd 不要设 `ProcessType=Background`。** 该设置将进程优先级降为 4,磁盘写入被限流,主线程阻塞在 `write()`,状态冻结。
- **launchd 日志路径不能含非 ASCII 字符**,否则启动失败(rc=78);系统层日志因此放在 `~/Library/Logs/deepml/`。

## 局限

- 单机采集:睡眠、断网期间无数据,报告中如实显示为缺口;不做多机冗余。
- `local_ms` 依赖本机时钟,未做 NTP 校准记录,延迟只可作相对比较。
- 仅记录前 10 档快照式变化,不含逐笔成交。
- 常驻服务脚本仅支持 macOS(launchd)。
